0 · 一页速览

一句话：这套插件不压缩历史，它管理"什么进上下文、什么时候移出、什么写成文件"。

上下文的一生有四个可以动手的位置，加上两个旁路机制，就是这个插件的全部：

少进来（无损）→ 记下来 → 移出去 → 早一点不给 → 隔离

阶段一句话作用位置主要产出状态
0 度量先知道 token 花在哪观测（旁路）token 归因报告、遮蔽收益模拟、判定结论前置，必做
1 读取纪律用工具契约决定"拿多少"请求发生前read / grep / bash / ls 的契约与阈值必做
2A 入口削减进来的东西先削一遍写入上下文前8 条确定性清洗规则 + 中部扫描 + 落盘必做
2B 出口移出看过之后把历史移出去下一轮组装时lag-1 遮蔽、偏移索引、recall按不等式决定
3 状态外部化该记的记到文件旁路（尾部注入）.pi/state/：计划 / 事实 / 判断 / 约束 / 交接长期价值最高
4 子 agent不该主线程看的别拿进来上下文边界契约化返回（结论 + 证据指针）最后做
三条贯穿全局的判断：
① 压缩作为质量手段被高估（模型升级会带走它的价值），作为成本手段成立但排在最后。
② 上下文的可靠性不能靠"记得"，只能靠"写下来 + 能校验"。
③ 先做不改变"模型看到什么"的机制：无损削减 > 状态外部化 > 移出去 > 提前少给。

1 · 为什么做，以及不做什么

1.1 起点

基于 pi 的 agent 跑到长会话时，token 成本与响应延迟失控；同时观察到明显的"记忆变形"：越到后面越容易重复踩坑、忘掉用户中途说过的约束、把早期错误判断当成既定事实。

直觉的解法是"压缩历史"。但这条路有三个结构性问题：

问题说明
字面量先死摘要保住"意思"，杀掉"具体"——确切的报错文本、行号、API 签名。而 40 步之后需要恰恰是具体
只有放大误差的通路每步结论 → 计划进度 → 会话摘要，层层继承。一个早期误判到最上层就变成"我们当初的决定"，没有任何环节会回头质疑
价值随模型升级归零摘要压缩的本质是"弥补模型读不了太长"。模型变强，这个补丁就贬值，而维护成本不变

1.2 因此的转向

不做"把历史压短"，改成三件互相独立的事：控制入口的粒度（阶段 1、2A）、控制历史的留存方式（2B，可选）、把状态从对话里搬到可校验的文件（阶段 3）。

这三件事的共同点是：它们不与模型能力竞争，而是与账单和可靠性竞争。

1.3 明确不做

不做原因
LLM 摘要式压缩历史前三行的问题；pi 内置 compaction 留作最后兜底
按重要性挑着削减/遮蔽破坏前缀缓存的 FIFO 性质，代价高一个数量级（见 §5.3）
二次合并（把多条记录合成一条）合并发生在老位置，等于全量缓存失效；且破坏"一次冻结"
跨会话的语义检索另一个问题，需要另一套存储；混进来会让本插件失焦
按 Agent 类型或流程阶段切换策略新增能力只指向"更早地少给信息"，与零容忍相悖；70 个键过筛后只剩 1 个维度真该随阶段变，不值一套 schema + 状态机 + 推断调用。这类知识属于 agent 自己，不属于插件
修改 pi 的 session JSONL源真相只读。任何写入都会让审计与回放失效
让模型自己维护状态不确定、每轮花 token、会漂移。状态必须按来源分权（§6.2）

2 · 全景架构

整个插件活在"消息组装"这一层：pi 从 session 树里取出可见消息之后、送给模型之前。所有机制都是这条链上的一个函数，全部可独立开关；在不改工具集的机制上（0 / 2A / 2B / 3），全关时输出与原生逐字节一致。阶段 1 一旦注册自己的 read，请求里的工具定义就变了、前缀随之改变，那条断言在那里不成立——它的基线只能是"插件未加载 + 重启进程"。

图 1 · 一条上下文进入模型前的完整链路。四个实心阶段是主链，两个旁路是度量与隔离。

2.1 三道工序的顺序不可调换

顺序为什么必须是这个顺序
pi compaction 先压缩之后才知道哪些消息还在上下文里，后面的工序都在它的结果上工作
2A 最后2A 只作用于最新一条。它的结果会成为下一轮 2B 的处理对象（这也决定了二者的收益关系，见 §9）

2.2 一个不可违反的物理事实

所有"改写历史"的手段，代价都不取决于改了多少，而取决于改动点之后还有多少内容。因为 prompt cache 按前缀命中：改了第 k 条，失效的是第 k 条之后的全部。

3 · 阶段 0 · 度量与归因

观测1 天离线 · 不调模型

3.1 解决什么

回答"token 到底花在哪"，以及"值不值得做后面四个阶段"。它不修改任何东西，只产出一份带结论的报告。

3.2 三个必须解决的坑

坑处理方式
双口径路径上出现 compaction 时，之前的历史不再进上下文但仍在文件里。必须同时统计 raw（全部）与 effective（实际送模型），否则增长斜率必错
固定开销单列工具定义、skills、AGENTS.md 注入、系统提示，常占 10–25%。不单列就会把"工具定义 12k"误判成"工具输出是大头"，然后做一个完全错方向的优化
估算要校准多 provider 无统一 tokenizer。用分桶估算（CJK 1.6 字/token、其余 3.8 字符/token）再用 usage 最小二乘拟合，报告 MAPE。MAPE > 30% 时报告只许输出占比，不许输出金额

3.3 能力

  • 五维归因：role / tool / path / turn / overhead，各出 top 10
  • 增长曲线与压缩事件的前后跳变，判断是否真的接近过窗口上限
  • 缓存抖动检测：逐轮对前缀区算 hash，相邻不同即报警并输出首个差异行
  • 遮蔽收益模拟：不写一行产品代码，先算出 2B 赚不赚，并输出 S 的分布
  • 重复错误检测：为阶段 4 的 A/B 预埋"是否重复踩同一个坑"的指标口径
这个阶段最可能的发现，会让你跳过半个插件。如果 prefix_instability > 0 且缓存命中率低，说明缓存是被自己废掉的（系统提示里的当前时间、每轮注入的 git status、插在历史前面的状态块）。修一行字符串就能拿回全部缓存收益——成本近零，收益可能超过所有削减机制的总和。

3.4 验收

≥3 个真实会话跑通；有 usage 的会话 mape_holdout ≤ 25%（前 80% 轮拟合、后 20% 轮预测的误差，不是全量拟合误差）；报告必须能直接回答四个问题（工具占比、top5 消耗源、是否值得遮蔽、缓存是否在抖）；只读断言分两种情形——已关闭会话校验全文 sha256，活跃会话只校验已读前缀并标注 live；同一输入两次运行输出逐字节相同。

4 · 阶段 1 · 读取纪律

请求前4 个半天无损零维护

4.1 核心判断

单次输出过大的根因不是"工具返回太多"，而是工具允许无参数地返回全部。read(path) 不传 offset 就返回全文，等于把"读多少"的决策成本全推给模型——而模型看不到文件行数、也感知不到 token，它没法做一个它没有信息去做的决定。

所以纪律必须在工具层，不是提示词层。提示词方案的三条死因：信息不对称（不知道文件多大）、注意力稀释（中段建议会被遗忘）、不可度量（违反了你也看不出来）。

图 3 · read 的三分支。阈值上调到 1500 行之后，大纲只用于"全文读进来本身有害"的区间，不再用来省中小文件的 token。

4.2 能力

工具契约要点
read三分支（≤1500 行全文 / 1500–20000 大纲 / >20000 只给大纲）；首行带规模头 842 lines · 24 symbols · sha；行号前缀 123| （需明确声明不要复制进 edit 的 oldText）；同 path+sha+range 在 5 轮内重复则只回一句提示；生成文件/二进制/minified 直接拒读
grep展开结果估算 ≤ 2k token 且条数 ≤ 50 时直接返行；否则返聚合计数（每文件命中数）。展开时 context=2，命中文件数 > 20 只回 top 20
bash不做日常截断：原样返回，只有超过 a7.hardCapTokens（20k token）才 head + tail + 中部扫描 + 落盘
ls/glob默认只列一层；条目 > 50 折叠；始终忽略 node_modules/dist 等
edit/write只回 changed hunks 与统计，不自动回读（回读是最常见的双倍开支）

4.3 一个必须诚实对待的账

局部修改型任务会从"读全文 1 次"变成"读大纲 1 次 + 读区间 1 次"，步数 +1。在多轮循环里，多一次工具调用 = 多一次完整的上下文前缀读（100k 上下文约 10k token 当量）。

所以这笔账是：省下约 10.9k 且此后每轮持续受益，一次性多付约 10k —— 回本 1–2 轮。长会话大赚，≤3 轮的短任务小亏。所有"改写上下文形态"的手段都有这个性质，不是本阶段独有。

4.4 验收与主 SLI

主指标不是总 token，而是 tokens_per_locate（从首次工具调用到首次 edit 之间花的 token），目标下降 ≥50%，步数增幅 ≤5%。另有一条双向指标 forced_full_read_rate，目标区间 5%–20%：太低说明模型不敢看全局（会写出局部正确的错误修复），太高说明大纲质量不合格。

5 · 阶段 2 · 削减与移出

2A 必做2B 按不等式决定

5.1 两块的分工

子块作用域时点缓存代价
2A 入口削减最新一条工具结果写入上下文前零（从未付过钱）
2B 出口移出历史工具结果已观察之后的下一轮w·m + (w−c)·S
2A 的安全边界：只能做确定性无损的削减。因为它发生在模型看到之前，赌错了模型连"被删了什么"都不知道。任何需要判断"这段重不重要"的操作都不属于 2A。2B 不同——模型已经看过原文，遮蔽是记忆整理，不是信息删减。这个区别决定了 2A 不能有损，2B 可以有损。

5.2 2A 的八条规则

ANSI 剥离、\r 覆写折叠、连续重复行折叠、空行压缩、行尾空白、超长单行截断、总量截断、非 UTF-8 容错。可逆性分三级：L0 纯表示层、L1 冗余消除、L2 有信息丢失。L2 必须先落盘成功，落盘失败则放弃变换、返回原文——宁可变大，不可丢数据。

作用域是硬约束，不是建议：除 ANSI 剥离与非 UTF-8 容错外，其余规则（含脱敏）只作用于命令输出，不碰 read/grep 的源码正文。read 返回的是可被 edit 原样回写的文本——删行尾空白会让 oldText 匹配失败，压空行会让行号与磁盘错位，\r 覆写折叠在 Windows 的 CRLF 源码上会把每一行清空，而脱敏会把 authorization: "Bearer ..." 这类源码字面遮掉，同样匹配失败。

最关键的一条补充是中部扫描：head/tail 截断必然切掉中间，而报错常在中间。截断时对丢弃的中段做一次错误行正则扫描，命中的最多 20 行插回。不做它，你的截断会真的丢掉那行 connection refused，然后模型开始瞎猜。

5.3 2B 的全部难点在"位置"

机制本身很朴素：最新的工具输出永远完整，上一轮的输出在下一轮被替换成一条凝固的小记录。真正的设计约束来自图 2 那个物理事实。

约束内容
一次冻结同一位置只写一次，渲染必须确定性（无时间戳、无随机量、不用 LLM），否则每轮文本微变，缓存全废
严格 FIFO边界只前进。淘汰回退、按重要性跳选、"补一刀"，全部按整段计费
使用机会覆盖证据必须已获得使用机会才可移出：被某条 decision 引用、或所属步骤已收尾、或其后已出现 ≥2 条新结果（三信号任一）。只看"有没有被结论点名"会让机制在第 3–5 轮永久停摆
移出 ≠ 删除原文必须仍可取得（JSONL 偏移或 blob），召回只能追加在尾部、不能回填
决策与渲染分离哪些位置该遮由纯函数 f(path, config) 决定（天然支持分支与崩溃恢复），遮什么由一次性冻结决定（保证确定性与缓存友好）

5.4 时序：为什么是"滞后一轮"

因为它正好夹在"观察到"与"再次需要"之间，是这个间隔的最小值。代价公式为：

Δ = w·m + (w−c)·S − c·M　，OpenAI c=0.5, w=1.0、DeepSeek c=0.1, w=1.0；S = 区段最后一条之后、上一轮已进入缓存的内容（不含本轮新增）加上区段内被跳过的空洞

两个量法都不能松：若 S 从区段第一条之后量，被遮蔽的内容会被算两次，方向都会翻；若把 pin / 已冻结项当成免费的洞，会漏掉 (w−c)·holeM。详见 interface-contract.md §4.1。

当 S ≈ 2k（一个回合）时，12k 的输出约 0.6–1 轮回本（OpenAI 侧立赚）；当 S ≈ 30k（改了 20 轮前那条）时，代价高一个数量级。所以 lag-1 不是"稍微好一点"，它就是这个方案能成立的唯一原因。

5.5 边际收益变小，但不为零（v1.1 修正）

图 4 · 边际收益变小不等于消失。判它划不划算要用不等式，不能用形容词。

判据（v1.2）：c·(M−m)·(R−t) > w·m + (w−c)·S，即"剩余轮数的累计节省"要大于"这一刀的一次性代价"。按对 2B 最不利的 M=2k, m=160, S=2k 代入：DeepSeek 需剩余 >11 轮，OpenAI 需剩余 >2 轮；M=12k 时 DeepSeek 只需 >2 轮。决策变量是会话还剩多少轮，不是 2A 有多强。「削减幂等性」修正为：只有 L2（有损削减）不重复，且 2B 遮蔽时复用已有的 blob；L0/L1 不阻止 2B。double_reduced_count 指"同一原始内容存在两个 L2 blob"，必须为 0。

6 · 阶段 3 · 状态外部化

长期价值最高5–6 天不省 token，省可靠性

6.1 它是唯一"减少上下文同时提高可靠性"的机制

2A 和 2B 都在减少上下文，代价是信息变少。状态外部化把易丢失的隐式状态变成可验证的显式文件，五个收益都不随模型升级消失：抗遗忘、抗虚报、可恢复、可审计、人机共编。

图 5 · 三个写者、各写各的文件、只有一个消费口。

6.2 核心机制（三条）

机制内容解决什么
按来源分权事实由 harness 写（只追加、放仓库外，模型只读）；判断由模型写（必须引用 fact id）；约束只有人能生效。三者物理分离到不同文件，越权写入由 edit/write 入口的路径守卫拦截并计数判断不会被当成事实继承
done_when计划条目由模型写；done_when 由模型提议，经静态检查（拒绝 file_exists / true 这类平凡谓词）与人确认后生效；status 由 harness 求值，模型不能改消灭"宣布完成"的虚报倾向
可推翻条件每条 decision 必须写：引用、被否决的备选与原因、可推翻条件结论不会变成不可质疑的教条

6.3 为什么"注入块恒定"是硬要求

如果注入块随轮数增长，它自己就成了新的膨胀源——Letta 的 memory block 就是这么烂掉的（没人修剪，涨到 8k token 每轮付费）。所以只注入活跃集：当前+下一步、全部生效约束、最近 3 条事实、未决判断、最多 3 条过期警告。

但只压大小不够——块本身不能留在历史里。每轮追加一块、旧的从不回收，50 轮就是 25k。所以注入块不写入 session，只在本次请求的尾部临时拼接、发完即弃：历史里从来没有它，也就不存在回收问题。这也是为什么它不依赖 2B 回收（2B 默认关闭，且排在阶段 3 之后）。验收要求单块 inject_tokens 的 P95/P50 < 1.3，且 inject_tokens_total ≈ 单块、inject_persisted = 0。

约束不按新旧截断。早期版本写"最多 10 条、超了按时间倒序截断"——那会让最早写下的常驻禁令（例如不许动 migrations/）第一个从模型眼前消失，而 constraint_violation = 0 随之失去意义。改为按人标注的优先级降级渲染（P0 全文 / P1 摘要 / P2 只计数），未标注的一律按 P0。

6.4 唯一真正的验收：冷启动

任务做到 60% 杀掉进程，新会话只加载 .pi/state/、不给任何对话历史，看能否继续做完，成功率 ≥ 80%。在这条通过之前，前面所有实现都只算"写了一堆文件"。

7 · 阶段 4 · 子 agent 隔离

最后做收益真实但被高估

7.1 它解决什么

"宽而浅"的探索——搜代码、读文档、跑一遍测试看结果——不需要污染主上下文。子 agent 在自己的窗口里烧，只把结论送回来。

7.2 一个必须戳破的幻觉

"构造性无损压缩"是假的。边界上的返回也是压缩，而且更不可验证——你连原文都没有了。除非返回的是契约化产物：结构化结果 + 证据指针（文件路径 / sha / 行区间）。自然语言摘要不算。

图 6 · 边界的形状决定了隔离是否真的有损。

7.3 什么时候不该拆（比"怎么拆"更重要）

情形原因
需要全局一致判断
（跨 20 文件改接口）		子 agent 各自局部正确，合起来错误。这类任务必须在一个上下文里做
任务边界说不清拆了要在边界来回传状态，比不拆更贵
预估 < 3 次工具调用固定开销 5–10k 吃掉全部收益
并行改同一片代码必须配 worktree 隔离或文件锁，否则冲突比省下的钱贵

7.4 代价

错误传播（主 agent 无法验证子 agent 的结论，只能抽查证据指针）、可调试性下降（跨 session 追踪，需要 trace id 串联父子）、固定开销。度量要看 subtask_cost_ratio（子任务开销 / 省下的 token）与 evidence_traceability（返回物带证据指针的比例）。

机制主要收益量级（估算）代价与风险
阶段 1（无损部分）重复读抑制、拒读、规模头、grep 小额直返总量 −5~10%几乎无；收益有限，但零风险

顺序的经济学（v1.1 重写）：旧版按"越靠前越便宜"排，得到 不产生 > 少进来 > 削一刀 > 移出去。在质量零容忍的前提下，这个排序要改：凡是改变"模型看到什么"的机制都往后放。新顺序是 少进来（2A 无损）→ 记下来（阶段 3）→ 移出去（2B）→ 早一点不给（阶段 1 视图改动）。 关键判断：阶段 1（读时少给）与 2B（读后拿走）的 token 收益高度重叠，但质量风险差一个量级——后者模型已经看过全文，前者没有。所以同样一块收益，应该交给 2B，而不是压给阈值。这也是为什么 2A 的日常截断被降级为紧急制动。

10 · 能力边界、风险与术语

10.1 它不承诺什么

  • 不让模型变聪明。它管的是账单和可靠性，不是能力。任务失败率不会因为装了它就下降（做对了也不会上升）。
  • 不消除上下文。它只是让上下文"进来得少、留得短、记得住"。
  • 不解决跨会话记忆。那需要另一套存储与检索，明确不在范围内。
  • 不对短会话划算。回本曲线决定了 ≤10 轮的任务基本无感，甚至略亏。

10.2 风险清单

风险可能性缓解
pi 扩展不支持覆盖原生工具中先花半天验证（图 7 的 go/no-go ①）；失败则只做 2A 的 bash 部分 + 阶段 3
收益不及预期（瓶颈不在上下文）中阶段 0 先量；若 effective_peak / window < 0.4，按成本而非质量决策
